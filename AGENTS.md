# Инструкции для Fusion Collection

## Контроль качества и команды разработки

Все команды выполняются из корня `fusion-collection`:

- Запуск приложения из исходников (со сплэш-экраном): `.\run.cmd` (или `uv run python -m fusion_collection`)
- Сборка исполняемого дистрибутива PyInstaller: `.\build.cmd`
- Обязательные проверки качества:
  - `uv run ruff check . --fix`
  - `PYTHONUTF8=1 uv run mypy . --pretty`
  - `uv run vulture`
  - `uv run pytest`

## Архитектурные и аппаратные инварианты

1. **Критическое ограничение безопасности ЦАП `ADAM-4021` (`+0.001 В`):**
   При подаче строгого нуля (`0.000 В`) с модуля `ADAM-4021` на управляющий вход силового блока печи ВТА силовая часть переходит в режим короткого замыкания и выбивает вводные автоматы. Поэтому к любому задаваемому напряжению `ADAM-4021` (включая `0.0 В` при сбросе и остановке нагрева) обязательно прибавляется смещение `SAFE_ZERO_OFFSET_V = 0.001` В. Удалять это смещение категорически запрещено.
2. **Проверка конфигурации модулей (`$AA2`) без молчаливой перезаписи:**
   При несоответствии настроек модулей `ADAM-4011`/`4021` требованиям программы приложение обязано сначала предупредить пользователя с показом полной распарсенной конфигурации и предложить применить требуемую конфигурацию (`%AANNTTCCFF`).
3. **Постоянный мониторинг и диагностика обрыва термопар:**
   Опрос модулей и показ живых данных (включая текущие выбранные типы термопар для каждого канала) работают непрерывно с момента подключения к оборудованию, в том числе вне записи измерения. При обрыве термопары (`abs(emf) >= 65.5` мВ) выводится канальное предупреждение без автоматического отключения нагрева (`format_open_tc_warning`), все зависящие от оборванного канала поля в UI (`Термопара 1`, `Температура`, `Скорость dT/dt`, `Термопара 2`, `Сигнал ДТА`) отображают статус `Ошибка`, а в журнал фиксируются только фронты смены состояния (`report_open_tc_transition`).
4. **Потоковая рабочая папка в AppData и формат сохранения `.fus`:**
   Во время активной записи отсчёты потоково сохраняются в рабочую папку `%APPDATA%/fusion-collection/recovery/` (`StagingDirWriter.create`) в распакованной структуре контейнера `.fus` (`manifest.json`, построчно буферизируемый `data.csv` с `os.fsync` каждые 10 с и `target.json`). При штатном завершении (`finalize_locked_file` / `save`) папка упаковывается в `.fus` через `fusion-common` и удаляется только после успешной записи; при старте `MainWindow` очищает пустые/битые папки (`prune_invalid_sessions`) и предлагает восстановить незавершённые записи (`find_pending_sessions`).
